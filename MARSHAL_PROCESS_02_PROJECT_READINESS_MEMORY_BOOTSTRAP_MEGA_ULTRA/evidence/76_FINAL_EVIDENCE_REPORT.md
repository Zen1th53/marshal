## Defects found and fixed

### P0-02-01 — A moved project could not be opened

`internal/app/runtime.go:228` compared the stored repository path against the
discovered root and treated any difference as `ErrConflict`. Reproduced at
baseline as a test, which failed with:

```
conflict: runtime repository identity differs
```

Moving a project is ordinary. At baseline it made the project permanently
unopenable. **Fixed** in `e43c858`: admission is decided by identity, so a
moved project opens and its recorded location is updated.

### P0-02-02 — Startup reported a moved project as fully READY

Verified against the built binary. After moving an initialized project, every
project dimension read READY while `app.Open` would have refused it — the
UI-versus-backend divergence Article XI forbids, introduced by Process 01's
assessment not knowing about identity. **Fixed** in `6cc2e3e`. Now:

```
$ marshal setup            # before the move
  [READY]   project.identity   This project's identity is confirmed.
$ marshal setup            # after the move
  [LIMITED] project.identity   This project has moved since it was last opened.
$ marshal setup            # holding another project's binding
Readiness: EXECUTION_BLOCKED
  [BROKEN]  project.identity   The project state here belongs to a different project.
```

The runtime refuses the last case with the same reason, so the two surfaces
cannot tell different stories.

### P1-02-03 — No stable identity to bind memory or evidence to

Every project was the constant `PROJECT-local`. Not a live leak (each project
has its own database) but it made identity positional. **Fixed** in `d24323b`.

### P1-02-04 — Two independent projects could share an identity

Found while running against real repositories: two projects scaffolded from
the same template in the same second produce byte-identical first commits and
therefore the same root commit hash. Deriving identity from that alone would
have made them one project, each seeing the other's memory. **Fixed** in
`e43c858` — every adoption mints a nonce, while the root commit still records
lineage so clone relationships stay visible.

### P1-02-05 — A copied binding read as a move

A copied `.marshal` directory is internally consistent and shares the lineage
it came from, so comparing evidence alone reported it as a move and admitted
it. **Fixed** in `e43c858`: distinguishing a copy from a move is a question
about the filesystem — whether the recorded location still holds the same
project — so `Resolve` asks it there and `Compare` stays a pure comparison.

### P1-02-06 — An absolute scope subpath was silently reinterpreted

`filepath.Join(root, "/etc")` yields `<root>/etc`, so a caller asking for a
path outside the project got a different path with no sign of it. Caught by
its own test; **fixed** in `5810d95` by refusing absolute subpaths.

## Process 00 integration

Process 02 is subordinate throughout. It classifies, observes and proposes;
every promotion decision goes to `constitution.GatePromotion`, which refuses an
AI as the promoting authority, refuses cross-project promotion, and refuses
unevidenced or contradicted candidates. Nothing in `projectmemory` can promote
anything; its output is candidates.

## Standard / ULTRA

Identity, scope and trust rules are mode-independent. ULTRA may hold more
projects at once; each keeps its own identity, memory and evidence, and
isolation is not relaxed. No mode-specific branch exists in this code, which is
what makes that structural rather than a policy that could drift.

## Limitations (stated plainly)

1. **No MARSHAL-mediated provider E2E.** No endpoint-enforcing egress exists in
   this environment. NOT_RUN is the only honest result; isolation was not
   weakened to obtain a pass.
2. **Memory source discovery is not wired to the filesystem.** The pipeline,
   trust model and gate integration are complete and tested, but nothing yet
   walks a project to *find* READMEs, instruction files and provider memory
   automatically. Sources are supplied by the caller. This is the largest
   remaining gap and is PARTIAL, not done.
3. **Clone and import flows are not exposed as commands.** The identity and
   readiness semantics they need are implemented and tested; `marshal clone`
   and `marshal import` do not exist.
4. **Web and MCP/A2A do not surface project identity.** They retain their
   existing behaviour, unchanged rather than weakened.
5. **`projectid.StateDirName` duplicates the `.marshal` literal** in
   `internal/project`. It is a named constant with a comment rather than a
   shared one, because importing `project` from `projectid` would invert the
   dependency. A mismatch would weaken copied-binding detection.
6. **Conflict detection is deliberately shallow.** It catches a statement and
   its negation. Anything subtler is left to semantic review; a missed conflict
   falls through rather than being asserted as agreement.
7. **The working tree still carries the unrelated uncommitted TUI work**
   present since Process 00, verified green and left untouched.
