# T49.A06 Runner Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Execute an exact, bounded T49 policy-test suite through the canonical T48 evaluator, persist typed case outcomes, emit the reserved case events, and finalize the durable run only through the A04-authorized lifecycle boundary.

**Architecture:** Keep policy-test semantics in `internal/policytest/engine.go` as a pure runner over the existing `policy.Evaluator` contract. Keep durable orchestration in `internal/store/policy_test_runner.go`, where the store can update the existing v9 case projection and reuse A04/A05 transaction and event primitives without an import cycle. The runner never calls `Runtime.Run`, providers, shell, network, or a production side-effect executor.

**Tech Stack:** Go, `context.Context`, existing T48 `policy.Evaluator`/`Decision`/`Effect`/`Obligation` contracts, SQLite v9 store, canonical `audit_events`/A05 event path, table-driven tests, race detector.

## Global Constraints

- Cases never execute actions; policy ALLOW is observation only.
- Use exact stored `PolicyID`, `PolicyBinding` (version/digest/generation), and test-file digest; never resolve “latest” or active policy.
- ResultStatus and RunState remain separate; expected DENY and expected typed errors are first-class passing assertions.
- Every privileged lifecycle mutation uses `Store.TransitionPolicyTestRunStateAuthorized`; no raw CAS or result setter is exported as a bypass.
- Case IDs are validated, complete, unique, and executed in deterministic lexicographic order.
- Case events contain bounded IDs/digests/status/reason facts only; no fixture, policy body, raw Decision, provider output, or backend error.
- Reuse A05 `policytest.case.passed` / `policytest.case.failed` event identity and `audit_events`; do not create another event graph or schema migration.
- Missing dependencies, malformed decisions/bindings, cancellation, and evaluator failures fail closed without false PASS or finalization.
- Provider labels are ordinary input and cannot change semantics; no external provider/API call is required.
- Do not implement A07 fuzzing, A08 recovery architecture, A09 observability/docs, A10 release integration, or CLI/protocol wiring beyond this runner boundary.
