**Status**: APPROVED DESIGN
**Date**: 2026-08-12
**Target Release**: `runtime-v0.4.0`
**Pack Version**: `6.0.0`
**MCP Version**: `2026-07-28`
**A2A Version**: `1.0`

---

## 1. Executive Summary & Objective

SLAVES Runtime v0.3.x established a production-hardened local control plane with verified Codex and OpenCode + local Ollama execution across Native CLI, MCP (2026-07-28), and A2A (1.0) protocols.

Runtime v0.4.0 proves that SLAVES is pleasant, observable, and reliable enough for daily engineering use.

### Core Goals
1. **Dogfooding & Operator Ergonomics**: Eliminate developer friction discovered during real SLAVES usage (e.g. default doctor human readability, stale PID handling, client HTTP timeouts during long LLM runs, CLI path lookup for `~/.local/bin`, dedicated execution logs and cancellation commands).
2. **Factual Provider Capability Model**: Replace conflated provider states with explicit, evidence-backed capability tracking (`IMPLEMENTED`, `INSTALLED`, `AVAILABLE`, `AUTHENTICATED`, `CAPABILITY-PROBED`, `REAL-E2E-VERIFIED`).
3. **Local Model Transparency**: Differentiate basic text generation from tool-calling, file-writing, and repository-mutation capabilities for local Ollama models.
4. **Gemini & Claude Provider Maturity**: Probe installed Gemini CLI (`0.50.0`) and Claude CLI (`2.1.218`), fix test runner duration units, add real E2E integration test harnesses, and report truthful verification status.
5. **Deterministic Verification & Hardened Supply Chain**: Preserve main branch protection, zero secret leakage, fail-closed bwrap sandboxing, and immutable v0.3.1 history.

## 2. Dogfood Friction Inventory & Root Causes

During Phase 3 baseline dogfooding, the following operational friction items were identified:

| Friction ID | Severity | Problem Summary | Root Cause | Fix in v0.4.0 |
|---|---|---|---|---|
| **FRICTION-1** | P0 | `slaves run` times out after 35s on long LLM runs | `api.NewClient` hardcodes `http.Client` timeout to 35 seconds, whereas real LLM tasks (e.g. OpenCode + Ollama) take 60-180 seconds | Configure client HTTP timeout dynamically or set run client timeout to 15 minutes (matching server run timeout) |
| **FRICTION-2** | P1 | `slaves doctor` without `--json` prints only `DEGRADED` or `PASS` with exit code | CLI text output formatter prints `string(report.Verdict)` without listing individual check results | Format human-readable checklist table in non-JSON doctor output showing pass/fail status and details per check |
| **FRICTION-3** | P1 | Installed provider binaries in `~/.local/bin` reported missing | `project.FindBinary` and `exec.LookPath` only check environment `$PATH`, which may omit `~/.local/bin` | Augment PATH lookup in `project.FindBinary` with `~/.local/bin` and standard user binary paths |
| **FRICTION-4** | P1 | Stale `.slaves/pid` file blocks daemon startup after unclean exit | `c.daemon()` uses `os.O_EXCL` on PID file without checking if PID process is still alive | Validate PID process liveness on startup; clean up stale PID files automatically |
| **FRICTION-5** | P1 | No command to view task execution logs or events | CLI only has `slaves events` (all events) and `slaves artifacts` | Add `slaves logs TASK-ID` (or `slaves task logs TASK-ID`) to tail/view stdout/stderr artifacts and execution events for a task |
| **FRICTION-6** | P1 | No CLI command to cancel an active task | Tasks can only be released, not explicitly cancelled via CLI | Add `slaves cancel TASK-ID` (or `slaves task cancel TASK-ID`) to signal cancellation to process supervisor |
| **FRICTION-7** | P1 | Gemini real test failed with 30ns timeout error | `gemini_real_test.go` initialized `worker.New(30, ...)` passing 30 nanoseconds instead of `30 * time.Second` | Fix duration argument to `30 * time.Second` |
| **FRICTION-8** | P2 | No capability probes distinguishing tool-calling vs text generation for local Ollama | Adapter probes only executed `binary --version` | Introduce structured capability probing for local Ollama models (`tool_calling`, `structured_output`, `repository_write`, `commit_capable`) |

## 3. Architecture & Data Model Changes

### 3.1 Provider Capability Data Model (`internal/model/capability.go`)

Represent provider state as structured, evidence-backed capabilities:

```go
type CapabilityState string

const (
	CapabilityUnknown     CapabilityState = "UNKNOWN"
	CapabilitySupported   CapabilityState = "SUPPORTED"
	CapabilityUnsupported CapabilityState = "UNSUPPORTED"
	CapabilityVerified   CapabilityState = "VERIFIED"
	CapabilityFailed      CapabilityState = "FAILED"
)

type EvidenceSource string

const (
	EvidenceStaticContract EvidenceSource = "STATIC_ADAPTER_CONTRACT"
	EvidenceBinaryProbe    EvidenceSource = "BINARY_PROBE"
	EvidenceAuthProbe      EvidenceSource = "AUTH_PROBE"
	EvidenceModelProbe     EvidenceSource = "MODEL_PROBE"
	EvidenceRealE2E        EvidenceSource = "REAL_E2E"
)

type ProviderCapability struct {
	Name         string          `json:"name"`
	State        CapabilityState `json:"state"`
	Source       EvidenceSource  `json:"source"`
	LastChecked  time.Time       `json:"last_checked"`
	Detail       string          `json:"detail,omitempty"`
}

type ProviderStatus struct {
	Name             string               `json:"name"`
	Implemented      bool                 `json:"implemented"`
	Installed        bool                 `json:"installed"`
	BinaryPath       string               `json:"binary_path,omitempty"`
	Version          string               `json:"version,omitempty"`
	Authenticated    CapabilityState      `json:"authenticated"`
	RealE2EStatus    CapabilityState      `json:"real_e2e_status"`
	Capabilities     []ProviderCapability `json:"capabilities"`
}
```

### 3.2 Enhanced Doctor Output (`internal/doctor/doctor.go`)

Doctor reports now provide complete visibility:
- **Default non-invasive check**: Quick binary, config, sqlite, bwrap, and auth metadata check (no model tokens spent).
- **Deep provider probe** (`slaves doctor --probe-providers` or `slaves adapters --deep`): Non-destructive model ping and tool capability test.
- **Human-readable text formatter**: Formats results as:
  ```text
  [PASS] git          - Git 2.48.1 is available
  [PASS] codex        - codex-cli 0.146.0 (/home/zen1th53/.local/bin/codex)
  [PASS] opencode     - 1.18.16 (/home/zen1th53/.local/bin/opencode)
  [PASS] ollama       - 0.32.6 (http://localhost:11434, default model: qwythos-9b)
  [PASS] gemini       - 0.50.0 (/usr/bin/gemini)
  [PASS] claude       - 2.1.218 (/home/zen1th53/.local/bin/claude)
  [PASS] bwrap        - strong local isolation is available
  ```

## 4. Operational CLI Enhancements

1. **`slaves run TASK-ID`**:
   - Accepts `--adapter ADAPTER` (default: codex)
   - Accepts `--model MODEL` (sets `SLAVES_OPENCODE_MODEL` / provider model override)
   - Extends HTTP client timeout to 15 minutes to prevent truncation during long model runs.

2. **`slaves logs TASK-ID`**:
   - Fetches recent runs, stdout/stderr artifacts, and events for `TASK-ID`.
   - Displays execution stdout/stderr in clean human-readable output or JSON.

3. **`slaves cancel TASK-ID`**:
   - Calls `runtime.CancelTask(ctx, taskID)`, marking cancellation in DB and signaling active worker processes.

4. **`slaves doctor`**:
   - Non-JSON output prints full human-readable checklist.
   - Accepts `--probe-providers` flag to trigger non-destructive deep capability probes.

5. **`slaves adapters`**:
   - Scans `$PATH` + `$HOME/.local/bin` + `/usr/local/bin`.
   - Displays implemented, installed, version, and capability status for all providers (`codex`, `opencode`, `gemini`, `claude`).
