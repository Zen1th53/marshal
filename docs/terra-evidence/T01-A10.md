# T01.A10 — Capability Broker Integration Evidence

## Scope

The T01 capability broker is integrated through the existing provider-neutral
`adapter.ProcessRunner` boundary. `app.Runtime.resolveAdapter` wraps the
runner with `adapter.NewCapabilityRunner` when an authenticated capability
broker is configured; the wrapper authorizes the exact subject, task, shell
resource, and `execute` action before the underlying process runner is called.
Provider clients do not implement separate capability semantics.

The broker itself has one durable Store contract. SQLite primary-key and
idempotency constraints provide the persistence boundary; the audit event
projection is bounded and uses a hashed resource reference. Metrics are
observational only.

## Security review result

- No-match is deterministic `DENY`.
- Revocation is durable and does not require agent restart.
- A foreign actor cannot retry a revoked grant as its own operation.
- Provider process execution is skipped unless the broker returns `ALLOW`.
- Raw resource text and secret markers are not written into capability events
  or metrics.
- The default runtime remains explicitly documented as legacy behavior when no
  capability broker is configured; it is not described as capability-enforced.

No separate evaluator, authorization engine, event store, or process runner
was introduced.
