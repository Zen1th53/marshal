# A2A 1.0 Mapping

## Why A2A

A2A is the remote agent-to-agent interoperability surface.

Agent OS uses it for communication between independently implemented agents
without exposing internal memory or tools.

## Mapping

```text
Agent OS remote agent identity
→ A2A Agent Card / discovered agent

Agent OS delegated unit
→ A2A Task

Agent OS message/data exchange
→ A2A Message + Parts

Agent OS produced remote output
→ A2A Artifact

Agent OS status events
→ A2A task/status streaming or supported async mechanism
```

## Version

Agent OS pins protocol compatibility to A2A major/minor `1.0`.

Patch releases are not used as the protocol compatibility key.

## Agent Cards

Public cards must not disclose:
- secrets,
- internal memory,
- internal-only tool topology,
- sensitive tenant metadata.

If card signatures are present, clients should validate them before trusting
capability claims.

## Trust

A remote A2A agent is an external principal.

Its messages and artifacts remain untrusted data until validated by task,
capability, data, and instruction-trust policy.
